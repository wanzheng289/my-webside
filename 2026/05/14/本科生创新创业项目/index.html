1. 项目缘起

这个项目的想法，来自我做家教时的一个观察。

带了一段时间小学生之后，我发现一件很有意思的事：孩子遇到不会的题，第一反应几乎不是思考，而是掏出手机搜题。即便在我旁边，也会先问 AI。这并不是懒，而是习惯了被动接收答案的信息获取方式。

但有一次，我让他把刚学会的知识点”教给我”——假装我是刚接触这个知识的学生。他立刻变得认真起来，开始一遍遍组织语言，自己在讲的过程中发现了好几处说不通的地方，主动翻书去查。那节课的效果，出乎意料地好。

这其实是教育心理学里早有实证的”费曼学习法”——通过教别人来倒逼自己深化理解。问题在于，这个方法需要一个随时可以被”教”的对象，而现实里家长不在身边、同学不方便、家教也不可能随叫随到。

于是我开始想：能不能让 AI 扮演这个”被教的学生”？不是 AI 教孩子，而是孩子教 AI。

这就是 FeynmanAgent 的起点。

2. 现有教育 AI 的问题

在设计这个系统之前，我梳理了一下当前教育 AI 产品普遍存在的几个核心问题。

问题一：单向灌输，学生永远是被动接受方

从学而思的九章大模型到 Khan Academy 的 Khanmigo，主流产品的底层逻辑都是”AI 作为全知教师单向输出知识”。即便是苏格拉底式提问，本质上也是教师视角——AI 已经知道答案，只是在引导学生说出来。这种模式容易让学生产生认知依赖，对 ADHD 倾向的孩子尤其不友好，因为被动接受的信息根本锚定不了注意力。

问题二：顺从性幻觉

这是把通用大模型用于教育场景最致命的问题之一。由于 RLHF 等对齐训练让模型倾向于输出”令用户偏好的回复”，如果孩子讲了一个错误的知识点，模型往往会附和甚至夸奖。这在教育场景里是直接的误导。

问题三：长对话中的遗忘与人设漂移

孩子跟 AI 学习往往不是一次性的，而是持续多天、多节课。通用模型在超长对话中容易忘记早期的学习上下文，而”虚拟学生”的认知状态和人设也会随着对话轮次逐渐漂移——原本应该”不会”的知识点，聊着聊着 AI 就”会”了。

这三个问题，是 FeynmanAgent 在架构上重点想解决的核心挑战。

3. 设计思路

3.1 翻转课堂：让孩子教 AI

FeynmanAgent 的核心交互范式是角色翻转——孩子扮演老师，AI 扮演一个有认知盲区的小学生。孩子需要向 AI 解释知识点，AI 根据孩子的讲解情况做出反应：讲对了就进一步追问、出变体题测验；讲错了就”装傻”，用变体错误句或疑问句引导孩子自己发现问题。

这个设计有几个关键好处：

  • 激活内部学习动机：被赋予”教师”角色之后，孩子会产生责任感，注意力锚定效果明显好于被动听讲
  • 倒逼知识重构：想教明白 AI，就得先把知识点的逻辑理清楚，知识盲区会在讲解过程中自然暴露
  • 对 ADHD 群体友好：传统被动模式极易让注意力难以持续的孩子走神，而”当老师”的互动形式能显著延长专注时长

3.2 前置隐式诊断：从架构层面解决顺从性幻觉

解决顺从性幻觉的关键，不是靠提示词”叫”模型不要附和，而是从架构上把”评判”和”生成”两个职责彻底解耦。

具体做法是：在主生成模型（MODEL2，扮演学生）给出回复之前，强制引入一个独立的诊断模型（MODEL1）先做判断。MODEL1 的唯一任务是：对比 RAG 检索出的 Ground Truth 与孩子的讲解，输出结构化的 JSON 诊断结果，包含是否有错、置信度、是否切换话题等字段。主生成模型只能基于这个诊断结果来生成回复，而不能自行判断对错。

这套”先校验、后生成”的机制有两个关键设计细节：

  1. 双模型隔离：MODEL1 和 MODEL2 调用不同的 API 端点，物理上切断了生成模型在接收到诊断结果后重新”想要附和”的内部注意力路径
  2. 置信度兜底：当孩子表述模糊导致诊断不确定时，系统不会强行给对/给错，而是路由至中性的”追问节点”，让孩子重新表述

这个思路的灵感来自大模型安全对齐领域里”LLM as Judge”的对抗性评估范式——在安全研究中，用独立模型客观评判输出是否合规；迁移到教育场景，就变成了独立模型客观评判孩子的讲解是否正确。

3.3 图状态机编排：精准控制对话流

自由对话模式下，模型很容易被孩子带偏——聊着聊着就变成了闲聊，或者跳出了”学生”的角色直接给答案。

FeynmanAgent 计划使用 LangGraph 构建一个有向状态图，把整个教学对话的流转路径明确编排出来：

每个节点的职责明确，条件边（Conditional Edges）根据诊断结果决定路由方向，不给模型任何”自由发挥”跳出流程的空间。

3.4 Harness 中间件管线：解耦复杂性

随着系统功能增多，如果把记忆管理、RAG检索、安全对齐、诊断调用等逻辑都堆在同一个节点里，代码会迅速失控。

参考业界的 Harness 架构范式，FeynmanAgent 计划把这些横切关注点封装成标准化的中间件管线，在用户输入到达核心生成节点之前依次拦截处理：

  • 安全对齐中间件：拦截越狱尝试、偏题行为（如孩子试图和 AI 闲聊）
  • 记忆中间件：从 Checkpointer/数据库提取当前知识点的历史状态和学情画像，注入上下文
  • RAG 中间件：检索 Ground Truth，并做缓存优化（同一知识点的多轮对话不重复检索）
  • 诊断中间件：调用 MODEL1，输出结构化诊断结果，带 Pydantic 校验和降级机制

这种解耦设计让每个模块可以独立迭代，也为后续扩展新学科、新诊断逻辑预留了接口。

4. 系统整体架构

整套系统计划分为五层：

① 前端交互层：基于 Vue 3 的响应式 Web 界面，支持流式渲染、思维链折叠面板、学情记录等组件。

② 后端服务层：分为 API 网关（FastAPI，处理鉴权、历史查询、学情档案 CRUD 等）和 LangGraph Server（处理流式对话、状态机路由和 Checkpointer 生命周期管理）。

③ Harness 智能体运行层：核心创新所在，包含中间件子模块（安全/记忆/RAG/诊断）和图状态机子模块（条件路由/追问/反问/测试/生成/归档节点）。

④ 数据存储层：关系型数据库（SQLite/PostgreSQL）存储账号信息、学情档案、Checkpointer 会话快照；向量数据库（Chroma）存储 Embedding 向量，支持 RAG 检索。

⑤ 知识库层：整理小学英语语法教材、大纲、例句等资料，经文本切分和向量化后存入向量库，作为诊断的 Ground Truth 来源。

5. 一个交互例子

以”现在完成时”这个知识点为例，走一遍完整的系统流程：

系统伪交互示意图

孩子输入：”现在完成时就是表示过去发生的事情，用 have 加动词就行了。比如’I have go to Beijing last year.’”

记忆中间件 提取上下文，注入学情画像（该孩子高频错点：时态混淆）。

RAG 检索 发现 current_topic_ground_truth 缓存为空，触发混合检索，获取并缓存 Ground Truth：

“现在完成时表示过去发生且与现在有关联的动作，结构为 have/has + 动词过去分词；若句中含 yesterday、last year 等明确过去时间状语，应使用一般过去时而非现在完成时。”

隐式诊断 MODEL1 对比发现两处错误：①概念定义不完整，将现在完成时混同于一般过去时；②动词形式错误，go 应为 gone。置信度 0.92，话题未切换。路由至反问节点。

主生成节点 MODEL2 结合”11 岁小学生”人设和诊断结果，生成回复：

“哦，老师！那我想说’我昨天吃了一个苹果’，是不是应该说’I have eat an apple yesterday’？”

这个回复用了一个变体错误句，故意把时间状语 yesterday 和现在完成时放在一起，引导孩子去发现两者之间的矛盾。如果孩子没发现，模型会进一步追问课本里的反例，促使孩子产生认知冲突，最终开始自我纠正。

6. 目前进展

这个项目目前已完成立项申请书的撰写和立项答辩，正在等待是否立项成功的通知。

现阶段主要在做两件事：

  • 技术调研：系统学习 LangGraph 生态，研读业界优秀的开源 Agent 框架源码，对 RAG 检索策略（混合检索、重排机制）进行选型评估
  • 知识库准备：收集整理小学英语语法教材资料，规划文本切分与向量化方案

按计划，后端核心架构（图状态机 + 中间件管线）将在 2026 年底前完成开发，前后端打通和系统集成在 2027 年初完成，2027 年 3-4 月进行小规模真实场景内测，最终于 2027 年 5 月结题。

设计这个系统的过程，让我意识到一件事：大模型本身的能力已经足够强，很多时候限制它的不是智能，而是缺少合理的工程约束。如何在不改动模型权重的前提下，用架构的手段让 AI 的行为可控、可解释、不跑偏——这或许是教育 AI 工程化落地最核心的问题。
